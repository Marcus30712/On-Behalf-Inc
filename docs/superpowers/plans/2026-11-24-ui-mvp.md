# On Behalf Inc — 계획 2: 도트 사무실 화면과 조작 (MVP) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 계획 1의 시뮬레이션 위에 PC 브라우저에서 바로 플레이할 수 있는 도트 사무실 화면과 조작 화면을 얹어 첫 플레이 가능한 버전(MVP)을 GitHub Pages로 배포한다.

**Architecture:** 화면은 `sim/game.js`의 `createGame / advance / act / save / load / view`만 쓴다. 순수 로직(시계 속도, 문안 채우기, 지도·길 찾기·캐릭터 이동)은 DOM 없는 모듈로 만들어 `node --test`로 검증하고, 캔버스 그리기와 DOM 패널은 얇게 두어 jsdom 테스트와 브라우저 검사(Playwright, Python)로 확인한다. 한 장의 `index.html`이 ES 모듈을 불러온다.

**Tech Stack:** 순수 JavaScript(ES 모듈), Canvas 2D, DOM. 테스트: `node --test`, 개발 의존성 `jsdom` 하나, 브라우저 검사 `python3` + Playwright(`/usr/bin/google-chrome`).

**Spec:** `docs/superpowers/specs/2026-11-24-on-behalf-inc-design.md` (특히 §5, §6, §8). 세계관 문안: `docs/superpowers/specs/2026-11-24-on-behalf-inc-copy.md`. 계획 1 판단 기록: `docs/superpowers/plans/2026-11-24-sim-core-rulings.md`.

## Global Constraints

- 빌드 없음, 런타임 외부 라이브러리 없음, 외부 그림·글꼴 파일 없음(도트 그림은 코드 안 데이터). 개발 의존성은 `jsdom`만.
- 라이선스: 없음(모든 권리 보유, © Marcus Shim).
- 다른 게임의 이름·그림·아이콘·화면 디자인·문장·고유한 이름을 쓰지 않는다. "진상"이라는 말을 쓰지 않는다.
- 한국어 화면 문구는 사용자 승인 후 구현한다(Task 1이 관문). 세계관 문안은 승인본을 그대로 쓴다.
- 화면은 `sim/game.js`의 공개 함수만 쓴다. `sim/`과 `world/`의 다른 모듈을 직접 import하지 않는다(문안 데이터 `world/events.js`, `world/advisor.js`, `world/research.js`, `world/traits.js`, `world/nations.js`, `world/clients.js`, `world/planet.js`의 **읽기 전용 문안** 표시는 예외).
- PC 웹 우선: 1280×720 이상에서 모든 패널이 가로 스크롤 없이 보인다. 1024×640에서도 깨지지 않는다.
- 저장: 하루가 끝날 때마다 자동 저장(`save`), 시작 시 `load`로 이어하기. localStorage 외 저장 없음, 서버 전송 없음.
- 같은 조작이면 같은 결과: 화면은 무작위를 쓰지 않는다(캐릭터 걷기 흔들림 같은 순수 연출도 사람 id로 정해진 값 사용).
- 시간: 1배속에서 영업 시간(평일 09:00~21:00)은 실제 1초에 게임 6분(12시간 = 120초). 영업 시간 밖과 주말은 실제 1초에 게임 120분으로 빨리 지나간다. 2·3배속은 이 값의 2·3배. 선택지가 있는 새 알림이 오면 자동 일시정지.

## Review Focus

1. **프레임마다 작은 시간 진행** — 30분보다 작은 조각으로 `advance`를 불러도 시계가 정확히 흘러간다(계획 1의 `pendingMinutes`). → Task 2 `clock` 테스트.
2. **문안 자리표시 채우기** — `{name} {client} {days} {holiday} {cand1} {cand2} {doneText}`가 이벤트 데이터로 모두 채워지고, 채울 값이 없는 문장(팀장·QA의 병가 알림의 `{client}` 문장, 도운 사람이 없는 공사 완료)은 문장째 빠진다. 화면에 `{`가 남지 않는다. → Task 3 테스트 + Task 9 브라우저 검사.
3. **떠난 사람·없는 고객사** — 퇴사자가 남긴 알림, 이탈한 고객사가 있는 상태에서 패널·지도가 깨지지 않는다. → Task 6·8 테스트.
4. **게임 오버와 이어하기** — 게임 오버 화면이 한 번 뜨고 더 진행되지 않으며, 새 게임을 시작할 수 있다. 망가진 저장이 있으면 새 게임으로 시작한다. → Task 8 테스트 + Task 9 브라우저 검사.
5. **길 찾기 막힘 없음** — 모든 좌석·자리·휴게실·출입구가 서로 연결되어 있고, 사람이 같은 칸에 겹쳐 멈추지 않는다. → Task 4 테스트.

### Task 2: 시계 (실시간 → 게임 시간)

**Files:**
- Create: `ui/clock.js`, `tests/clock.test.js`

**Interfaces:**
- Consumes: `advance(state, minutes) → minutesSimulated`, `view(state)` (계획 1)
- Produces:
  - `SPEEDS = [0, 1, 2, 3]`
  - `gameMinutesFor(realMs, speed, { day, minute }) → number` — 영업 창(평일 09:00~21:00) 안이면 `realMs/1000 × 6 × speed`, 밖이면 `× 120 × speed`. 0배속이면 0.
  - `createClock({ state, now }) → { speed, setSpeed(n), tick(realNowMs) → { advancedMinutes, newEvents: number[] /*새로 생긴 inbox index*/, dayEnded: boolean } }` — `tick`은 지난 tick 이후 실제 시간을 게임 분으로 바꿔 `advance`를 부르고, 한 번에 최대 게임 240분까지만 진행한다(탭이 멈췄다 돌아와도 폭주하지 않게). 선택지가 있는 새 알림이 생기면 `speed`를 0으로 바꾼다.
- [ ] **Step 1: 실패하는 테스트**
  - `1x runs 6 game minutes per real second in opening hours` (`gameMinutesFor(1000, 1, {day:0, minute:600}) === 6`)
  - `outside hours and weekends run fast` (`minute: 1300` → 120, 토요일 → 120)
  - `small ticks still move the clock`: 1배속에서 16ms마다 1000번 `tick` → `view(state).minute`가 09:00에서 정확히 약 96분(± 30) 앞으로.
  - `a long pause does not run away`: 실제 1시간 뒤 `tick` 한 번 → 진행 ≤ 240분.
  - `a new choice event pauses the clock` (테스트용 상태에 선택지 알림이 생기도록 `act`/`advance` 진행)
  - `speed 0 advances nothing`
- [ ] **Step 2: 실패 확인** — `npm test` → FAIL
- [ ] **Step 3: 구현**
- [ ] **Step 4: 통과 확인** — PASS

### Task 4: 사무실 지도, 길 찾기, 사람 이동 (순수)

**Files:**
- Create: `render/map.js`, `render/path.js`, `render/actors.js`, `tests/map.test.js`, `tests/actors.test.js`

**Interfaces:**
- Consumes: `view(state).people[]`의 `id, role, activity ('phone'|'break'|'task'|'idle'|'off'), task, health, shiftToday`, `view(state).research.done`
- Produces:
  - `MAP = { width: 20, height: 12, tiles: string[] /*행마다 문자열*/, spots: { seats: [x,y][8], leadDesk, qaDesk, breakRoom: [x,y][4], taskTable: [x,y][3], clinic: [x,y], door: [x,y] } }` — 16px 타일, 위에서 내려다본 사무실. 벽 `#`, 바닥 `.`, 책상·의자·소파 등 문자는 Task 7이 그린다. 연구 완료 시설(휴게실 개선·의무실·교육 테이블)은 처음부터 자리가 있고, 완료 전에는 "공사 전" 모습으로 그린다.
  - `findPath(MAP, from, to) → [x,y][] | null` — 4방향 BFS, 벽·가구 칸은 못 지나감(자리 칸 자체는 도착 가능).
  - `targetFor(person, slotIndex) → [x,y]` — phone → 그 사람의 좌석(`seats[slotIndex]`, 상담사 순서), break → 휴게실 빈 자리, task → 업무 테이블(코칭·연구·교육) 또는 QA 책상(qa), idle → 자기 자리, off·아픔·휴가·결근 → 출입구 밖(화면에 안 그림).
  - `stepActors(actors, people, dtMs) → actors` — 사람마다 `{ id, x, y, path, target }`, 초당 3칸 속도로 이동, 목표가 바뀌면 새 경로. 두 사람이 같은 칸에서 멈추지 않도록 휴게실·업무 테이블 자리는 사람 순서대로 나눈다.
- [ ] **Step 1: 실패하는 테스트**
  - `every spot is reachable from the door and from every seat` (Review Focus 5)
  - `no two spots share a tile`
  - `phone agents go to their own seat, break goes to the break room, off leaves`
  - `two people on break never get the same break spot`
  - `actors reach their target and stop`: 3초 분량 `stepActors` 뒤 목표 칸에 도착.
  - `a person who left disappears from actors`
- [ ] **Step 2~4:** 실패 확인 → 구현 → PASS
