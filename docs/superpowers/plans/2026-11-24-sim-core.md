# On Behalf Inc — 계획 1: 시뮬레이션 규칙 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 화면 없이 돌아가는 고객센터 시뮬레이션 규칙(사람·달력·대기열·사건·연구·채용·돈·저장)을 만들고, 테스트와 자동 진행으로 검증한다.

**Architecture:** `sim/`은 화면을 모르는 순수 ES 모듈이다. 게임 상태는 직렬화 가능한 평범한 객체 하나(`GameState`)이고, 모든 규칙은 `(state, rng) → state를 바꿈` 함수로 30분 구간과 하루 단위로 진행한다. 세계 데이터(나라·휴일·특성·고객사·연구·사건 문안)는 `world/`에 데이터로만 둔다. 계획 2(도트 화면과 UI)는 `sim/game.js`의 공개 함수만 쓴다.

**Tech Stack:** 순수 JavaScript(ES 모듈), Node 20+의 `node --test`. 런타임 외부 라이브러리 없음, 빌드 없음.

**Spec:** `docs/superpowers/specs/2026-11-24-on-behalf-inc-design.md`

## Global Constraints

- 빌드 없음, 런타임 외부 라이브러리 없음. 개발용 의존성도 이 계획에서는 없음(`node --test`만).
- 라이선스: 없음(모든 권리 보유, © Marcus Shim). 단 `sim/erlang.js`는 큐크래프트에서 복사하며 파일 머리의 pyworkforce MIT 표시(Copyright (c) 2021 Rodrigo Arenas)를 그대로 둔다.
- 다른 게임의 이름·그림·문장·고유한 이름을 코드, 데이터, 주석, 커밋 메시지 어디에도 쓰지 않는다.
- 한국어 문안은 사용자 승인 후 구현한다(Task 1이 관문). "진상"이라는 말을 쓰지 않는다. 특정 실제 나라의 법을 다루지 않는다.
- 출신 나라는 달력·휴일·주간 휴일 선호에만 영향을 주고, 특성·기술·능력에는 영향을 주지 않는다.
- 첫 프로젝트 운영: 월~금 09:00~21:00, 주말 휴무. 근무조 이른 조 09:00~18:00, 늦은 조 12:00~21:00.
- 첫 버전 인원: 상담사 8, 팀장 1, QA 1. 상담사 좌석 8.
- 구간 30분. 같은 시드면 같은 결과(모든 무작위는 `sim/rng.js`로).
- 저장은 localStorage 한 칸(키 `on-behalf-inc:save:v1`). 서버 전송 없음. 저장 형식에 버전 번호.
- 시간 단위: 시뮬레이션 내부는 분(minute). 하루 = 1440분, 구간 = 30분.

## Review Focus

1. **처리 능력보다 콜이 많은 구간(응대 인원 0명 포함)** — 예외나 NaN 없이 서비스 레벨 0~1, 포기 콜 ≥ 0을 낸다. → Task 3 `queue overload` 테스트.
2. **출신과 능력의 독립** — 같은 시드로 나라만 바꿔 만든 사람의 특성·기술이 같다. → Task 6 `nation does not change traits or skills` 테스트.
3. **저장·불러오기 왕복** — 휴가 중인 사람, 진행 중 연구·공사, 대기 중 알림, 채용 중 후보가 있는 상태를 저장했다 불러와도 같고, 망가진 저장이나 버전이 다른 저장은 새 게임으로 안전하게 처리한다. → Task 12 테스트.
4. **휴일 경계** — 주말에 걸린 휴일, 두 나라 휴일이 같은 날, 해마다 날짜가 바뀌는 휴일이 연말을 넘어가는 경우. → Task 4 테스트.
5. **게임 오버는 한 번만** — 월말 돈이 0 미만이 되거나 마지막 고객사가 떠나는 순간 한 번만 `gameOver`가 서고, 그 뒤 진행 함수는 상태를 바꾸지 않는다. → Task 11 테스트.

### Task 3: 구간 대기열 (얼랑 C + 포기)

**Files:**
- Create: `sim/erlang.js` (큐크래프트 `staffing-calculator/erlang.js` 그대로 복사, 머리 주석 유지), `sim/queue.js`, `tests/queue.test.js`

**Interfaces:**
- Consumes: `sim/erlang.js`의 `trafficIntensity, serviceLevel, occupancy, averageWait`
- Produces: `intervalQueue({ calls, ahtMin, agents, targetSec, patienceSec }) → { offered, handled, abandoned, serviceLevel /*0~1*/, asaSec, occupancy /*0~1*/ }`

- [ ] **Step 1: 실패하는 테스트**
  - `matches Erlang C when staffed`: `calls 100, ahtMin 4, agents 18, targetSec 20` → `serviceLevel`이 `erlang.serviceLevel(18, trafficIntensity(100,4), 4, 20/60)`와 소수 6자리까지 같고, `abandoned`는 `offered`의 5% 미만.
  - `queue overload`: `agents 0`과 `agents 5`(강도 13.3)에서 예외 없음, `serviceLevel === 0`(0명) 또는 `0 ≤ SL < 0.2`(5명), `abandoned > 0`, `handled + abandoned === offered`, 모든 값이 유한수.
  - `no calls`: `calls 0` → `serviceLevel 1`, `abandoned 0`, `occupancy 0`.
  - `longer patience abandons less`: 같은 과부하에서 `patienceSec 30` 포기 수 > `patienceSec 120` 포기 수.
- [ ] **Step 2: 실패 확인** — `npm test` → FAIL
- [ ] **Step 3: 구현** — 인원 > 강도이면 얼랑 C로 SL·ASA·점유율을 내고, 포기율 = `P(wait) × (1 − exp(−patience / (평균 대기 조건부)))`로 근사. 인원 ≤ 강도이면 처리 가능량 = `agents × 30 / ahtMin`, 넘친 콜은 포기, SL은 처리 가능량 비율에 비례해 0~0.2 사이로 낮게, 점유율 1. 값은 모두 정수 콜(`Math.round`)로 맞춘다.
- [ ] **Step 4: 통과 확인** — `npm test` → PASS

### Task 6: 사람

**Files:**
- Create: `sim/people.js`, `tests/people.test.js`

**Interfaces:**
- Consumes: `createRng` (Task 2), `TRAITS`, `NAMES` (Task 5)
- Produces:
  - `Person = { id, name, role: 'agent'|'lead'|'qa', nation, traits: string[1..2], skills: { handling, systems, coaching, evaluation } /*0~10, 소수*/, fatigue, stress /*0~100*/, morale /*0~100*/, health: { kind: 'well'|'sick'|'burnout'|'leave', daysLeft }, probationDays, history: { highStressDays } }`
  - `createPerson(rng, { id, role, nation }) → Person` — 특성·기술은 `rng`에서만 정한다(나라를 읽지 않음). 이름만 `NAMES[nation]`에서.
  - `ahtFor(person, client) → number` — `client.ahtMin × (1.3 − handling × 0.03 − systems × 0.02) × traitMul × (1 + fatigue/200)`, 수습 중이면 × 1.25.
  - `applyWork(person, { minutes, occupancy, mods }) → void` — 피로 `+ minutes/30 × (1.5 + 2.5 × occupancy) × fatigueGainMul`, 스트레스 `+ minutes/30 × (0.5 + 3 × max(0, occupancy − 0.7) / 0.3) × stressGainMul`.
  - `applyRest(person, { minutes, mods }) → void` — 피로 −2/30분, 스트레스 −1/30분, × `restRecoveryMul`.
  - `overnight(person) → void` — 피로 −40, 스트레스 −8 (0 미만 없음).
  - `moraleOf(person) → number` — `100 − 0.4 × fatigue − 0.6 × stress + recentBoost` 를 0~100으로 자름.
- [ ] **Step 1: 실패하는 테스트**
  - `nation does not change traits or skills`: 같은 시드 두 rng로 `nation` A·B를 각각 만들면 `traits`, `skills`가 같고 이름만 다르다.
  - `skilled people handle faster`: handling 9 사람의 `ahtFor`가 handling 2 사람보다 작다.
  - `probation is slower`: `probationDays > 0`이면 `ahtFor` × 1.25.
