# On Behalf Inc v1.4 — 다듬기 설계 (짧은 설계)

- 날짜: 2026-11-25
- 상태: 추천안으로 진행 승인(2026-11-25, "다음 버전 추천하는대로 진행"). 새 한국어 문구는 `2026-11-25-v1.4-copy.md`에서 따로 승인받는다.
- 출처: v1.2·v1.3 판단 기록의 "다음 버전으로 미룬 것"

## 왜

v1.2(주말·확장)와 v1.3(채널)을 거치며 화면 문구가 전화 시절 그대로 남았고, 몇 가지 작은 어긋남이 쌓였다. 새 기능 없이 플레이어가 보는 어색함과 틀린 정보를 걷어 낸다.

## 목표

1. **채널 중립 문구:** "전화 응대", "전화를 함께 받아요", "서비스 레벨부터 올려요"처럼 채팅·이메일에 맞지 않는 문장을 바꾼다(문구 승인 필요).
2. **지원 중 표시:** 자기 고객사가 닫혀 다른 고객사를 돕는 상담사는 업무 패널·사람 카드에 그 사실이 보이고, 지도 아이콘도 실제로 응대하는 채널을 따른다.
3. **쉬는 날 지표:** 그날 문을 열지 않는 고객사의 지표 칩은 "아직" 대신 쉬는 날이라고 보인다.
4. **화면 넘침:** 고객사가 5곳 이상이어도 1280×720에서 페이지가 스크롤되지 않는다(지표 줄이 두 줄 안에 들어가거나 줄여 보인다).
5. **규칙 어긋남:**
   - 이탈 경고는 그 고객사가 문을 여는 날에만 발행된다.
   - 확장이 끝난 달의 임대료는 완공일부터 날짜 비율로 낸다.
   - 회사 단위 타이머(제안 연속 일수, 채용 대기, 공사 일수)는 주말 고객사가 있어도 월–금만 센다. 사람 단위 타이머(결근, 휴가, 퇴사 예고)는 지금처럼 본인 근무일을 센다.
6. **근무표:** 주 6일 경고 칸에 열 제목을 단다. 이미 승인된 `roster.colDaysWeekend`를 쓰고, 6일 경고 열 제목은 새 문구.
7. **정리:** 중복 코드(`channelLabel`, 도움받은 이름 합치기, UI의 임대료 계산) 하나로, 지도 표시 캔버스 상태 저장, 이메일 SL 상한 고정, 불러온 밀림 형태 검증, 쓰지 않는 승인 문구 연결 또는 정리(`expansion-start` 사건은 공사 시작 때 실제로 띄움).

## 하지 않는 것

새 고객사·새 채널·새 연구, 영어 화면, 모바일, 자동 플레이 정책 재설계, 수치 재조정(규칙 어긋남 수정으로 숫자가 움직이면 기록만 하고 점검은 그대로 통과해야 함).

## 성공의 증거

- 평일 전화만 하는 게임 골든 파일 그대로(규칙 수정 5는 주말·확장·채널이 있을 때만 영향).
- 각 수정마다 실패하던 테스트가 통과(문구는 화면에 찍히는 글자 그대로 확인).
- 기존 자동 플레이 점검 19개 통과. 숫자가 바뀐 줄은 밸런스 문서 v1.4 절에 기록.
- 브라우저 점검: 고객사 5곳 상태에서 페이지 높이 ≤ 720.
