# v1.9 휴식표 직접 조정: 설계

- 날짜: 2026-11-27
- 상태: 사용자가 "추천하는 방향으로 진행"으로 방향을 승인함(하루 단위, 데스크톱 우선). 문구는 `2026-11-27-v1.9-copy.md`에서 따로 승인받음.
- 로드맵: `2026-11-26-roadmap-draft.md`의 v1.9

## 의도

v1.6부터 팀장이 콜 볼륨을 보고 휴식을 배정한다. 스케줄링 능력이 낮은 팀장은 바쁜 시간에 휴식을 몰아 넣는다. 실제 운영 매니저는 팀장이 짠 휴식표를 보고 바쁜 구간에 쉬는 사람이 몰리지 않게 고친다. 이번 버전은 플레이어가 그 일을 직접 해 보게 한다. 팀장의 스케줄링이 낮을수록 고칠 거리가 많아진다.

## 목표 / 하지 않을 것

- **목표**
  - 오늘 휴식표를 시간대별 예상 콜과 함께 한눈에 본다.
  - 사람마다 휴식 세 개(오전 휴식, 점심, 오후 휴식)를 15분씩 앞당기거나 미룬다.
  - 바뀐 휴식표는 그날 시뮬레이션에 바로 쓰인다.
- **하지 않을 것**
  - "매일 이 시간" 같은 고정 규칙
  - 다음 날 휴식표 미리 짜기
  - 휴식 길이 바꾸기, 휴식 빼기
  - 끌어서 옮기기, 휴대폰 전용 화면(이번엔 버튼 방식)
- **피할 것**
  - 휴식을 정해진 창 밖으로 보내거나 이미 시작한 휴식을 바꾸는 것
  - 밸런스가 바뀌는 것(자동 플레이는 휴식표를 고치지 않으므로 23/23과 숫자가 그대로여야 한다)

## 접근 (검토한 것)

1. **새 탭 "휴식표" (선택).**
   - 탭 줄에 근무표 옆으로 추가한다. 위에는 30분 칸마다 예상 콜 막대와 쉬는 사람 수를 보여 준다. 아래 표에는 사람마다 휴식 세 개의 시각과 앞당기기·미루기 버튼을 둔다.
   - 전체를 보면서 고칠 수 있어 운영 매니저의 실제 화면과 가깝다.
2. 사람 카드 안에서 고치기. 한 사람씩만 보여서 "바쁜 칸에 몰렸는지" 판단할 수 없다.
3. 지도에서 끌어 옮기기. 재미있지만 범위가 크고, 접근성과 테스트가 어렵다.

## 규칙

- **행동** `moveBreak { personId, kind: 'am'|'lunch'|'pm', start }`. `start`는 그날 0시부터 센 분이다.
- **거절 사유** (순서대로 확인한다)
  - `unknown-person`: 센터에 없는 사람이다.
  - `not-working`: 오늘 근무하지 않는다.
  - `bad-break`: 잘못된 휴식 종류이거나 15분 칸에 맞지 않는다.
  - `break-started`: 현재 휴식이나 새 시작 시각이 지금(`state.minute`)보다 이르다. 이미 시작했거나 지난 휴식, 그리고 지난 시각으로는 옮기지 않는다. 같은 시각은 허용한다.
  - `break-window`: 그 사람 근무조의 창(`windowsFor`)을 벗어난다.
  - 모두 통과하면 `{ ok: true }`를 돌려준다.
- **저장**
  - 오늘 계획을 확보한다(`ensureBreakPlan`). 그 사람의 항목이 없거나 근무조에 맞지 않으면 그 사람만 새로 짜서 넣는다.
  - `plan[id][kind] = start`로 바꾸고, `plan[id].edited = true`를 표시한다.
  - 이 표시는 그날만 남는다. 다음 날 새 계획이 만들어지면 사라진다.
- **세 휴식은 겹치지 않는다.** 창이 서로 겹치지 않기 때문이다(오전 60–180, 점심 180–330, 오후 근무 길이−180 이후, 근무 시작부터 센 분).
- **시뮬레이션**: 구간 계산은 이미 저장된 계획(`breakLookup keep`)을 읽으므로 바꾼 휴식이 그대로 쓰인다.
- **근무조가 바뀐 경우**: 그날 근무조가 바뀌어 항목이 맞지 않게 되면 그 사람 휴식은 새로 짜인다(지금 규칙과 같다). 직접 바꾼 내용은 사라진다.
- **세이브**: VERSION은 1 그대로 둔다. `edited`는 선택 필드라 v1.8 세이브를 그대로 읽는다.

## 휴식표 화면 정보 (`view.breakBoard`)

`breakBoard(state)`는 sim 쪽 순수 함수이며 아래를 돌려준다.

- `slots`: 오늘 문을 여는 시간대의 30분 칸 목록. 칸마다 `{ minute, calls, away, busy }`가 들어 있다.
  - `calls`: 전화·채팅 고객사의 예상 콜 합계(`expectedCalls`, 반올림 전 값). 이메일은 쌓아 두었다 답하므로 뺀다.
  - `away`: 그 칸에 1분이라도 휴식 중인 상담사 수
  - `busy`: 오늘 칸들 가운데 예상 콜 상위 25% 안에 들면서 `away`가 2명 이상인 칸
- `rows`: 오늘 근무하는 사람마다 `{ personId, breaks: { am, lunch, pm }, edited }`가 들어 있다.
  - 휴식마다 `{ start, earlier, later }`를 준다. `earlier`와 `later`는 15분 앞이나 뒤로 옮길 수 있는지다(위 규칙과 같은 판단).
- `by`: `'lead'` 또는 `'auto'`
- `lead`: 그날 휴식표를 짠 팀장 이름

## 화면

- 탭 이름은 "휴식표"이고, 탭 줄에서 근무표 바로 뒤에 둔다.
- 위쪽: 30분 칸 막대
  - 높이는 예상 콜을 나타낸다.
  - 막대 아래에 쉬는 사람 수를 적는다.
  - `busy` 칸은 경고색으로 칠하고 경고 문구를 붙인다.
  - 칸마다 마우스를 올리면 설명이 보인다.
- 아래쪽: 사람 표
  - 열은 이름, 역할, 휴식 세 개다.
  - 휴식 칸마다 시각과 ◀(15분 앞당기기)·▶(15분 미루기) 버튼이 있다. 옮길 수 없으면 버튼을 끈다.
  - 직접 바꾼 사람은 "직접 조정" 표시를 단다.
- 맨 위 한 줄은 누가 짰는지 보여 준다(팀장 이름 또는 자동 배정).
- 거절되면 패널 아래 알림 줄에 이유를 보여 준다(기존 방식).
- 숫자 규칙: 예상 콜은 건수라서 정수로 보여 준다.
