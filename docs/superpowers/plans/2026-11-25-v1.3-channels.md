# v1.3 Channels (chat, email) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a chat client and an email client, each unlocked by research and offered like other clients, with chat run as a concurrent queue and email as a backlog with an open-hours deadline.

**Architecture:** Each client def gets `channel` ('phone' default). Chat reuses `intervalQueue` with effective seats (people × 2 × 0.75). Email is a new pure module `sim/backlog.js` that keeps per-client mail batches stamped in "open minutes" and returns a queue-shaped result so satisfaction, today-stats and fatigue reuse the phone path. UI reads `view.clients[].channel` and email metrics.

**Tech Stack:** vanilla ES modules, Canvas 2D, `node --test` (Node 22), jsdom, Python Playwright browser check.

**Spec:** `docs/superpowers/specs/2026-11-25-v1.3-channels-design.md` · approved copy `docs/superpowers/specs/2026-11-25-v1.3-copy.md`

## Global Constraints

- Korean strings verbatim from the approved copy; no invented Korean text; never "진상"; no other game names anywhere; no real country's law; numbers are 가상 값.
- Weekday phone-only games stay byte-identical: `tests/fixtures/weekday-golden.json` must pass unchanged (never regenerate it).
- Save key stays `on-behalf-inc:save:v1`; saves without `backlog` or client `channel` load and play.
- Assignment kind stays `{ kind: 'phone', clientId }` for every channel (save compatibility); the client's `channel` decides how the work runs. Comment this where the kind is defined (`sim/interval.js` header).
- Chat: `CHAT_CONCURRENCY = 2`, `CHAT_EFFICIENCY = 0.75` (exported from `sim/interval.js`).
- Email deadline: `slTarget: { pct: 90, openMinutes: 720 }`; chat target `{ pct: 80, sec: 60 }`. Fees 20,000 (saebyeol-bank, chat, veltora) / 12,000 (solbang-books, email, kamuen). Both weekday 09–21.
- Unlock: client `requiresResearch: 'chat-desk' | 'mail-desk'`; offered only when that id is in `state.research.done`.
- Implementers do not commit; the controller commits.

## Review Focus

1. Email client accepted with nobody assigned → mail goes overdue after 720 open minutes and satisfaction falls until churn (Task 3 test `unstaffed email client loses satisfaction`).
2. Friday-evening mail over a weekend → does not age while closed, still waiting Monday 09:00 (Task 3 test `open minutes stop while closed`).
3. Old save (v1.2, no `backlog`, client without `channel`) → loads, plays a day, email clients absent (Task 3 test `v1.2 save loads without backlog`).
4. Email or chat client with v1.2 cover rule → agent whose own email client is closed covers an open client; email batches never get processed while the email client is closed (Task 3 test `closed email client gets no processing`).
5. Particle settling on new copy with numbers (`{n}통이에요`, `{fee}예요` with 20,000/12,000) renders correctly (Task 4 literal-string test).

**Interfaces:**
- Consumes: `channelOf`, `callsFor`, `todayEntry`, `satisfactionDelta` (Task 2 / existing).
- Produces:
  - `state.backlog[clientId] = { openMin: number, items: [{ at: number, n: number }] }` (oldest first).
  - `export function stepBacklog(entry, { arrivals, agents, ahtMin, targetMin }) → { offered, handled, abandoned: 0, serviceLevel, asaSec: 0, occupancy, overdue }` — advances `entry.openMin` by 30, appends `{at: openMin-after, n: arrivals}` when arrivals>0, processes `floor(agents*30/ahtMin + carry)` mails oldest-first (keep the fractional remainder in `entry.carry`), counts `onTime` = processed with `openMin - at <= targetMin`; `overdue` = unprocessed mails whose age crossed `targetMin` during this interval; `offered = processed + overdue`; `serviceLevel = offered ? onTime/offered : 1`; `occupancy = min(1, processed*ahtMin/(agents*30))` (0 when agents 0).
  - `export function backlogCount(entry) → number`.
  - Event `backlog-warning` {clientId, data:{n}} pushed at most once per 5 workdays per client when `backlogCount >= BACKLOG_WARN = 120` at end of day.
  - `view.clients[i].channel`; for email `view.clients[i].backlog` and `view.clients[i].onTime` (today's `inTarget/offered`, or null).
- Email clients advance only while open (`isOpen`): closed intervals touch nothing.
