# v1.7 Lead Hiring Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When there is no lead (or the only lead is leaving), the player can hire a new lead from two candidates.

**Architecture:** Add an optional `role` to the existing single-slot `state.hiring`. Role changes only the cost, the wait, the candidates' role and what happens on hire. A new `lead-candidate` event reuses the candidate choice ids. The UI adds a lead block to the hiring tab and a warning line on the people tab.

**Tech Stack:** vanilla ES modules, `node --test` + jsdom, tools/autoplay.js, tools/browser_check.py.

**Spec:** `docs/superpowers/specs/2026-11-26-v1.7-lead-hiring-design.md`. Approved copy is in `docs/superpowers/specs/2026-11-26-v1.7-copy.md`.

## Global Constraints

- All Korean strings come verbatim from the approved copy doc. Do not invent new copy.
- Display rule: coaching and planning skills show exactly 2 decimals (6.00). Money and counts are integers.
- `LEAD_HIRE_COST = 3000`; lead wait 5–7 Mon–Fri workdays; the agent flow is unchanged (1500, 3–5).
- Hired lead: no probation; roster `early` on weekdays 0–4; assignment `{ kind: 'coaching' }`.
- One hiring at a time, whatever its role.
- Save compatibility: `VERSION` stays 1 (ruling: the spec's "VERSION은 올리지만" would break loading v1.6 saves). A `hiring` with no `role` means agent.
- No other game names. No "진상".

## Review Focus

1. A v1.6 save that is mid-hiring (no `role`) keeps advancing as an agent search → test in Task 1.
2. The lead is on `state.leaving` and the player hires a new one → after the old lead leaves there is exactly one lead, and `needsLead` stays false while the new lead is in → test in Task 1.
3. A lead search is running and a second lead arrives somehow (for example, both candidates are offered twice) → `hireCandidate` refuses when `needsLead` is false → test in Task 1.
4. A lead hire must not take an agent seat: with every agent seat full, lead hiring still starts → test in Task 1.
5. The hiring tab during an agent search shows the lead block's `busy` line, not a start button → test in Task 2.

  - Event `lead-candidate` has data `{ cand1, cand2, c1, c2, p1, p2 }`, where c = `skills.coaching` and p = `planningOf(person)` as raw numbers.
  - The view adds `needsLead: boolean` and `leadLeaving: boolean` (true when a lead exists but every lead is on `state.leaving`).
  - The action is `{ type: 'startHiring', role?: 'lead' }`.
