# v2.3 휴식표 고정 규칙: 판단 기록

- 설계: `../specs/2026-11-27-v2.3-break-rules-design.md`(짧은 설계로, 계획 역할도 함께 한다)
- 문구: `../specs/2026-11-27-v2.3-copy.md`(11-27 승인)

## 판단 (Ruling)

| 판단 | 이유 | 틀렸을 때 비용 |
|---|---|---|
| 고정 휴식을 먼저 놓고, 무작위 뽑기 횟수는 고정 여부와 상관없이 같게 한다 | 고정이 없으면 계획이 전과 똑같다. 자동 플레이 숫자와 골든 계획이 그대로다 | 없음 |
| 화면용 계획의 캐시 키에 규칙을 넣었다 | 고정이나 풀기 뒤에 아직 저장되지 않은 항목(근무조가 바뀐 사람 등)이 새 규칙으로 다시 짜이게 하려는 것이다 | 없음 |
| 오늘 휴식을 옮겨도 규칙은 그 규칙이 오늘 쓰였을 때만 함께 옮긴다 | 최종 검토: 다른 근무조로 일한 날 휴식을 옮기면 평소 규칙(예: 이른 조 점심 12:30)이 사라졌다. 고치기 전 실패, 고친 뒤 통과를 테스트로 확인했다 | 없음 |
| 오늘 이미 지난 휴식도 고정할 수 있다 | 고정은 다음 날부터 쓰인다. 오늘 휴식표는 바꾸지 않는다 | 없음 |
| 주중 골든을 다시 만들었다 | 새 게임에 `breakRules: {}`가 생긴 것뿐이다(검토자가 확인함) | 없음 |

## 다음 버전으로 미룬 것

- 세이브를 불러올 때 규칙 값이 15분 단위 시각인지까지는 확인하지 않는다. 고장 난 세이브에서는 이상한 시각이 "맞지 않음"으로 보일 수 있다. 플레이로는 생기지 않는다.
- "팀장이 정했어요" 안내는 팀장이 없는 날(자동 배정)에도 같은 문구다. 승인된 문구라 그대로 두었다.
- 세이브에 남은, 없는 사람의 규칙은 퇴사 처리에서만 지운다. 게임에서는 쓰이지 않는다.

확인: npm test 566/566, autoplay 23/23(숫자 변화 없음), browser_check 통과(고정 흐름 점검을 추가했고, 규칙을 끄면 실패하는 것을 확인).
