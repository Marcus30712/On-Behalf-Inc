# On Behalf Inc — v1.1 다듬기 (설계 + 구현 계획)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** MVP를 플레이해 보며 드러난 다섯 가지를 고쳐, 알림이 덜 시끄럽고 화면이 정확하며 손을 놓으면 이기지 못하는 게임으로 만든다.

**승인:** 사용자 2026-11-25 "1번 - 3번까지 추천하는 옵션으로 진행하는 것 승인, 커밋 & 푸시 단계별로 진행 승인". 이 문서의 선택은 모두 추천안이다.

**Spec:** `docs/superpowers/specs/2026-11-24-on-behalf-inc-design.md` (§2 목표·안티목표: 아무것도 안 하면 몇 달 안에 사람이 지치고 평판이 떨어져야 한다). 계획 1·2 판단 기록: `docs/superpowers/plans/2026-11-24-sim-core-rulings.md`, `…-ui-mvp-rulings.md`.

## 접근법

- **A. 수치와 규칙을 조금씩 고치기 (선택)** — 새 시스템 없이 기존 규칙의 빈도·누적·표시를 바꾼다. 작고 되돌리기 쉽다.
- B. 새 시스템 추가(예: 직원 성장 곡선, 고객사 요구 변화) — v1.2 확장에서 다루는 편이 맞다.

## Global Constraints

- 계획 1·2의 제약을 그대로 따른다(빌드 없음, 외부 라이브러리 없음, 다른 게임 이름 금지, "진상" 금지, 화면은 `sim/game.js`만, 같은 시드 같은 결과, 운영 시간·근무조·인원·좌석 고정).
- 새 한국어 문구를 만들지 않는다. 승인된 문구(`ui/text.js` `UI_TEXT`, `world/*.js`)만 쓴다.
- 기존 저장 형식과 호환: 새 필드는 없으면 기본값으로 읽는다(옛 저장도 불러와진다).
- 모든 기존 테스트와 `tools/autoplay.js`의 균형 점검, `tools/browser_check.py`가 계속 통과해야 한다(바뀐 수치가 있으면 균형 기록에 남긴다).

## Review Focus

1. 옛 저장(v1.0)을 불러와도 오류가 없다.
2. 금요일 휴무 요청이 줄어도 "주간 휴일 차이"라는 장치는 살아 있다(1년에 사람마다 몇 번은 나온다).
3. 자동 일시정지 안내는 기다리는 선택이 하나라도 남아 있는 동안만 보인다.
4. 손 놓고 하기(idle)는 잘 운영하기(sensible)보다 확실히 나쁘다. 손 놓고 하기가 돈·평판에서 이기는 시드가 하나도 없다.
5. 처리된 알림을 접어도 새 알림·선택지 알림은 항상 보인다.

### Task 2: 손 놓고 하기는 이기지 못하게 (sim 밸런스)

**Files:** Modify 필요한 `sim/*.js`·`world/*.js` 수치; `tools/autoplay.js`; `tests/balance.test.js`; 균형 기록

- [ ] 실패하는 점검(autoplay와 balance 테스트에 추가): 시드 10개 360일에서
  - 손 놓고 하기의 연말 돈이 같은 시드의 잘 운영하기보다 모든 시드에서 낮다.
  - 손 놓고 하기가 평판 S 이정표를 얻는 시드가 2개 이하다.
  - 손 놓고 하기에서 시드 10개 중 7개 이상이 1년 안에 한 명 이상을 잃는다(퇴사) 또는 게임 오버.
  - 기존 점검 9개는 그대로 통과.
- [ ] 조정 방향(추천안, 실행자가 수치를 정함): 코칭·휴식 연구 없이 시간이 지나면 사기가 서서히 떨어지게(장기 피로 누적), 사기가 낮은 사람의 퇴사 예고 확률을 키우고 기본 처리 "보내 준다"가 실제로 사람을 잃게, 고객사 콜 양이 분기마다 조금씩 늘어 그대로 두면 서비스 레벨이 무너지게(잘 운영하기는 업무 배치와 팀장·QA 전화 응대로 버틸 수 있는 정도).
- [ ] 바뀐 값을 균형 기록에 표로 남기고 autoplay 출력 첨부.
