# On Behalf Inc — 계획 1 밸런스 기록 (Task 13)

- 날짜: 2026-11-24
- 도구: `node tools/autoplay.js` (공개 API `createGame / advance / act / view`만 씀), 테스트 `tests/balance.test.js`
- 시드: 1~10 (확인용으로 11~40도 돌림)

## 조정 전 상태

모든 시드에서 29일째 두 고객사를 다 잃고 게임 오버. 이유:

- 콜 양(하루 360·320콜)이 상담사 고객사당 4명(이른 조 2 + 늦은 조 2)으로는 거의 모든 구간에서 감당이 안 됨(구간 대부분 과부하).
- 만족도가 구간마다 크게 움직임: 나쁜 구간 하나에 약 −2.6, 하루면 −60. 첫날 만에 70 → 약 1.
- 대기열 과부하 구간에서 상담사를 5명에서 13명으로 늘려도 포기 콜이 78로 같음(Task 3에서 넘긴 문제).

**SL 측정 방법:** 여기서 "평균 SL"은 `view().clients[].today.serviceLevel`, 즉 그날 목표를 맞춘 구간의 비율(R14의 "met" 판정과 같은 값)이다. 고객사·근무일마다 하나씩 모아 평균 낸다. 콜 수로 가중한 진짜 서비스 레벨은 view에 없다(계획 2 넘김 목록에 이미 있음). 구간 비율이 더 엄격하다.

**정책:**
- `idle`: 아무 결정도 하지 않는다. 선택 알림은 마감 때 기본값(휴가 허락, 금요일 그대로, 퇴사 보내 줌, 후보 보류, 제안 거절)으로 처리된다.
- `sensible`: 휴가 허락 / 금요일 휴무 요청은 그대로 둠(고객사·근무조당 2명이라 1명 빼면 그 조가 무너짐) / 금요일 마감 때 고객사·근무조마다 스트레스 60 이상인 사람 중 가장 높은 1명에게 다음 주 금요일 휴무 / 연구 clinic → rest-room → stress-training → flexible-shifts, 팀장이 16:00~18:00 연구 / 같은 근무조에서 한 고객사가 2명 이상 적으면 1명 이동 / 자리 나면 채용, 첫 후보 선택 / 퇴사 예고는 붙잡기 / 새 고객사 제안 거절.

## 조정 과정 (요약)

1. 대기열을 Erlang A로 바꿈 → 과부하 평탄 해소. 만족도를 날 단위로. 콜 양·곡선을 4명 팀에 맞춤 → 게임 오버는 없어졌지만 스트레스가 매일 0, 만족도는 100에 붙음.
2. 스트레스 식(기본 + 점유율 비례), 밤 회복 비율, 코칭·QA 효과 축소 → 아무것도 안 하면 지치지만 합리적 플레이는 금요일 휴무 허락 때문에 금요일이 무너지고(37%) 고객사를 잃음.
3. 합리적 정책: 금요일 휴무 요청은 그대로, 쉬는 날은 스트레스 높은 사람만 금요일에 → 팀장·QA가 반복 번아웃(전화 밖 업무 점유율 0.5가 너무 높음) → 0.2로.
4. 연구가 돕는 순간이 시드당 0.7 → 병 확률·기간 증가, `HIGH_STRESS` 40, 완공을 다음 근무일 낮으로 → 2.0.
5. 다른 시드(11~40) 확인 중 시드 26이 고요의 달(1.6명 → 1명)에서 무너짐 → 소수 인원 섞기. 이후 30/30 생존.
6. 스트레스 기본값 1.0 → 1.1 → 1.15 → 1.2: 아무것도 안 할 때 번아웃 ≥ 2인 시드 7/10 → 8/10, 합리적 플레이는 시드당 1년 평균 약 2번.

## 남은 걱정

- **동시에 쉬는 휴식:** 같은 근무조 두 사람이 같은 시각에 쉬어(11:00, 16:00, 19:00) 하루 세 구간은 사실상 1명뿐이다. 구간 달성률이 약 87%를 넘기 어렵다. 휴식을 사람마다 엇갈리게 하는 것은 근무표 규칙(Task 7) 변경이라 하지 않았다.
- **합리적 플레이의 여유:** 시드 1~10 최저 74.6%, 시드 11~40 최저 73.1%로 기준 72%에 가깝다. (시드 11~40: 아무것도 안 하면 30/30 지침·번아웃 ≥ 2는 26/30, 합리적 플레이 30/30 생존, 1년 번아웃 시드당 2.1, 연구가 돕는 순간 시드당 2.0.)
- **의무실이 아픈 사람을 고치는 순간**은 시드 10개 중 3개 정도. 나머지 "도움" 알림은 휴게실·교육이 스트레스 높은 사람을 덜어 주는 것.
- **이름 중복:** 시작 인원 10명 중 같은 이름이 있는 시드가 100개 중 35개(예: 시드 1의 p6·p8 "토 리셀"). 알림에서 누가 누군지 헷갈린다. 이 작업 범위 밖.
