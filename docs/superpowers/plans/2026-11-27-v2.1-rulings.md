# v2.1 휴대폰 화면 휴식표: 판단 기록

- 설계: `../specs/2026-11-27-v2.1-mobile-breaks-design.md`(짧은 설계로, 계획 역할도 함께 한다)
- 사용자 결정(11-27): 범위는 "패널 + 휴식표". 사무실, 알림, 지표 배치는 그대로 둔다.

## 판단 (Ruling)

| 판단 | 이유 | 틀렸을 때 비용 |
|---|---|---|
| 휴대폰에서는 탭 줄을 화면 맨 아래 한 줄로 고정하고, 시트를 그 위에 연다 | 처음 구현에서는 시트가 탭 줄을 덮었다(휴대폰 브라우저 점검이 잡음) | 탭이 8개라 뒤쪽 탭 3–4개는 옆으로 넘겨야 보인다 |
| 시작·안내·확인 창(`.overlay`)의 z-index를 20으로 올렸다 | 최종 검토: 고정한 탭 줄(11)이 창 위로 눌렸다. 데스크톱에서는 원래 창이 위에 있었다 | 없음 |
| 시트 최대 높이 = 보이는 화면 − 탭 줄 − 측정한 위 막대 높이(`--topbar-h`, `100dvh`, `100vh` 대체) | 위 막대가 두세 줄로 접혀 돈·평판 줄을 가렸다. 설계의 75vh는 맞지 않았다 | 화면 높이가 아주 낮으면 시트가 작아진다(안에서 스크롤) |
| 근무표·달력·고객사 표는 휴대폰에서 폭을 줄이지 않고 시트 안에서 옆으로 스크롤한다. 근무표 이름은 한 줄로 둔다 | 최종 검토: 이름이 한 글자씩 줄바꿈되었다. 설계의 "옆으로 스크롤" 약속 | 없음 |
| 휴식표 카드는 같은 표 DOM을 CSS로 바꾼다 | 데스크톱과 같은 코드, 테스트, 버튼을 쓴다 | 일부 화면 읽기 프로그램이 표 구조를 읽지 못한다(아래 미룬 것) |

## 다음 버전으로 미룬 것

- 탭 줄이 넘칠 때 옆에 더 있다는 표시가 없고, 고른 탭이 자동으로 보이게 스크롤되지 않는다.
- 휴대폰 카드에서는 화면 읽기 프로그램이 사람 이름을 버튼과 함께 읽지 않을 수 있다(버튼 이름에 사람 이름 추가).
- 아이폰 아래쪽 안전 영역(`safe-area-inset-bottom`)은 지금 설정(`viewport-fit=cover` 없음)에서는 필요 없다.
- 게임 전체 휴대폰 화면(사무실 크게, 알림·지표 재배치)은 다음 후보로 남긴다.

확인: npm test 551/551, autoplay 23/23, browser_check 통과(휴대폰 390×844 점검 포함), 스크린숏 확인.
