# On Behalf Inc v1.2 — 새 문구 (사무실 확장·주말 프로젝트)

상태: 승인 2026-11-25

- 날짜: 2026-11-25
- 쓰임: 계획 `2026-11-25-v1.2-expansion.md` Task 1의 결과물. 승인되면 Task 5·7이 이 문구를 `world/`와 `UI_TEXT`로 그대로 옮긴다.
- 읽는 법: 표마다 맨 왼쪽 칸이 영문 키(코드에서 쓰는 이름)다. 키는 그대로 두고 **한국어 문구만** 고쳐 주면 된다. "메모" 칸은 설명이며 화면에는 나오지 않는다.
- 자리표시: `{stage}` 확장 단계 이름, `{cost}` 금액, `{days}` 날 수, `{rent}` 월 임대료, `{seats}` 상담사 좌석 수, `{n}` 숫자, `{name}` 사람 이름, `{client}` 고객사 이름, `{sl}` 서비스 레벨 목표, `{fee}` 월 계약금.
- 기존 승인 문구(세계관 문안 `2026-11-24-on-behalf-inc-copy.md`, 화면 문구 `2026-11-24-on-behalf-inc-ui-copy.md`)는 바꾸지 않는다. 숫자는 모두 **가상 값**이며 Task 8에서 다시 맞춘다.

### 1.2 공사 거절 이유 (`refuse`)

기존 `refuse.no-cash`는 채용 비용 문장이라 공사용 키를 따로 둔다.

| 키 | 언제 | 문구 |
|---|---|---|
| `refuse.office.no-cash` | 돈이 공사 비용보다 적음 | 돈이 모자라요. 공사 비용은 💰 {cost}예요. |
| `refuse.building` | 이미 공사 중 | 이미 공사를 하고 있어요. 끝난 뒤에 다시 넓혀요. |
| `refuse.max-level` | 더 넓힐 곳이 없음 | 더 넓힐 곳이 없어요. |
| `refuse.need-previous` | 확장 1 전에 확장 2를 누름 | 창가 구역을 먼저 넓혀야 해요. |

> 확인 필요: 코드가 거절 이유를 `no-cash` 하나로 돌려준다면, 화면이 어떤 패널에서 눌렸는지 보고 `refuse.office.no-cash`를 고르게 해야 한다.

### 3.1 제안 문장 (`client-offer` 보완)

기존 `client-offer` 본문에는 "좌석이 8개뿐이라"와 결과에 "세 고객사"가 들어 있어 새 고객사에는 맞지 않는다. 기존 문구는 그대로 두고, 확장 뒤 제안에는 아래 문장을 쓴다.

| 키 | 문구 | 메모 |
|---|---|---|
| `client-offer.textMore` | {client}에서 계약을 제안했어요. 목표는 {sl}, 월 계약금은 {fee}예요. 받으면 지금 인원을 나눠야 해요. | 평일 고객사 제안 본문 |
| `client-offer.textWeekend` | {client}에서 주말 계약을 제안했어요. 토·일 09:00~18:00에 전화를 받아요. 목표는 {sl}, 월 계약금은 {fee}예요. | 주말 고객사 제안 본문 |
| `client-offer.acceptMore` | {client}가 새 고객사가 돼요. 업무 배치에서 응대 인원을 정해 주세요. | `accept` 결과 (확장 뒤) |
| `client-offer.acceptWeekend` | {client}가 새 고객사가 돼요. 근무표에 토·일 칸이 생겼어요. 주말 조를 짜 주세요. | 주말 고객사 `accept` 결과 |
| `client-offer.again` | 예전에 인연이 닿지 않았던 {client}에서 다시 연락이 왔어요. | 재제안일 때 본문 맨 앞에 덧붙임 |

## 4. 근무표 주말 (`roster`, `shift`)

| 키 | 문구 | 메모 |
|---|---|---|
| `shift.weekend` | 주말 / 주말 조 | 칸 안(짧게) / 전체 이름 |
| `roster.colDaysWeekend` | 월 · 화 · 수 · 목 · 금 · 토 · 일 | 주말 고객사가 있을 때 요일 열 머리 |
| `roster.weekendHelp` | 토·일 칸은 주말 조 → 휴무 순서로 바뀌어요. 주말 조는 09:00~18:00예요. | 표 위 안내에 한 줄 더 |
| `roster.weekendCount` | 주말 조 {n}명 | 토·일 열 아래 합계 |
| `roster.sixDays` | 주 6일 이상 일해요. 피로가 빨리 쌓여요. | 그 사람 줄 끝에 경고 (빨간 점 옆 툴팁에도) |
| `roster.sixDaysShort` | 주 {n}일 | 이름 옆 작은 경고 표시 |

> 확인 필요: 기존 `refuse.bad-weekday`("근무표는 월~금만 정할 수 있어요.")는 주말 계약이 없을 때만 맞다. 그대로 두고 주말 계약이 없을 때만 쓰는 것을 제안한다.

## 5. 위쪽 바·지표 (`topbar`, `metrics`)

| 키 | 문구 | 메모 |
|---|---|---|
| `topbar.weekendOpen` | 주말 운영 | 주말 고객사가 있을 때 토·일에 `주말 휴무` 대신 |
| `metrics.weekendOnly` | 주말 운영 | 평일에 주말 고객사 지표 줄에 숫자 대신 |
| `metrics.weekendOnlyTip` | 이 고객사는 토·일에만 전화를 받아요. | 위 표시의 툴팁 |
| `tasks.seatsOf` | 상담사 좌석 {n} / {seats} | 기존 `tasks.seats`의 "8"을 좌석 수로 바꾼 판 |

> 확인 필요: 기존 `tasks.seats`("상담사 좌석 {n} / 8")는 승인 문구라 고치지 않고 새 키 `tasks.seatsOf`를 제안한다. 그냥 기존 키에 `{seats}`를 넣는 편이 낫다면 알려 주세요.
