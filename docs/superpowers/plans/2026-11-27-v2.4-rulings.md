## 판단 (Ruling)

| 판단 | 이유 | 틀렸을 때 비용 |
|---|---|---|
| 팀장과 QA 채용을 하나의 표(`STAFF`)로 묶었다 | 팀장과 같은 흐름이라 중복 코드를 만들지 않는다. v1.7 테스트는 그대로 통과한다 | 없음 |
| QA 지원자 알림에는 기술 점수 대신 특성을 보여 준다 | 게임에서 QA 점검량은 특성(꼼꼼함 1.2배)으로만 달라진다. 기술 점수를 보여 주면 잘못 고르게 만든다 | 없음 |
| 자동 플레이 점검 기준은 1년 평균 만족도(10판 중 8판 이상) | QA가 바꾸는 것은 만족도다. 차이가 작아 여유가 1뿐이다 | 밸런스를 바꾸면 이 점검이 먼저 흔들릴 수 있다 |
| "다른 채용이 끝나면…" 문구는 팀장 문구(`hiring.lead.busy`)를 같이 쓴다 | 문구 초안에서 같이 쓰기로 했다 | 없음 |

| 최종 | 손상된 세이브에 `constructor` 같은 이름의 채용 역할이 있어도 상담사 채용으로 돈다(`Object.hasOwn`) | 최종 검토: `STAFF[role]`가 물려받은 속성을 찾아 매 근무일 오류가 났다. 이전에는 상담사 채용으로 돌았으므로 되돌림이다. 고치기 전 실패, 고친 뒤 통과를 테스트로 확인했다 | 없음 |

## 11-28 추가 규칙에서 내린 판단

| 판단 | 이유 | 틀렸을 때 비용 |
|---|---|---|
| 팀장의 "커뮤니케이션 스킬"은 코칭 기술로 본다. 설득 확률 = 코칭 / 10 (10%~90%) | 게임에 커뮤니케이션 기술이 따로 없다. 면담·코칭이 가장 가깝다. 팀장 코칭은 5~8이라 대개 50~80% | 기술을 따로 만들면 바꿔야 한다 |
| 면담은 통보 다음 날 하루 끝에 결과가 난다(팀장이 그날 쉬어도) | "24시간 내로"를 하루 단위 게임에 맞췄다 | 없음 |
| 팀장이 여럿이면 코칭이 가장 높은 팀장이 면담한다. 팀장이 없으면 예전처럼 플레이어가 고른다 | 팀장이 없으면 면담할 사람이 없다 | 없음 |
| 팀장·QA의 퇴사 통보는 지금처럼 플레이어가 고른다 | 규칙이 상담사만 말했다 | 없음 |
| 붙잡는 중(면담하고 붙잡아 본다)이어도 채용할 수 있다 | "통보 알림이 발생하면 그 시각 부로 채용 가능" | 철회되면 자리가 없어 취소될 수 있다(규칙대로) |
| 채용은 한 번에 하나지만, 지원자를 고르면 그 채용은 끝나고 합류 대기 목록(`joining`)으로 간다. 다음 채용을 바로 시작할 수 있다 | 합류까지 3~10주라, 고른 뒤에도 자리를 붙잡으면 증설 뒤 4자리를 채우는 데 4달이 걸렸다(자동 플레이 3개 실패). 합류 대기자는 좌석과 직급 자리를 차지한 것으로 센다 | 동시에 여럿이 합류 대기할 수 있다. 화면은 채용 탭 목록으로 보여 준다 |
| 이미 겹쳐 일하는 중에 철회되면 둘 다 남고, 상담사는 좌석이 빌 때까지 교육 테이블에서 일한다 | 합류한 사람을 내보낼 규칙이 없다 | 좌석이 계속 모자랄 수 있다 |
| 저장 파일의 QA 맡은 상담사는 첫 활성 고객사 상담으로 바꾼다 | 상담사는 QA를 맡을 수 없다 | 없음 |
| 새 문구(면담 알림·결과·채용 취소 조언 등)는 승인된 문구 말투로 썼다 | "추천 옵션으로 진행 · 커밋 & 푸시 승인" | 바꾸려면 다음 버전에서 |
| 자동 플레이 QA 재채용 점검은 120일째부터 비교한다(30일 퇴사 + 합류 최대 70일 + 20일) | 새 QA가 오기 전에는 양쪽 모두 QA가 없다. 1년 평균이면 차이가 묻힌다(5/10). 120일부터는 8/10 | 기준 여유가 0이다 |
| 자동 플레이는 퇴사 통보한 상담사 자리를 빈자리로 보고 미리 뽑는다 | 새 규칙에서 합리적인 플레이 | 없음 |

## 다음 버전으로 미룬 것

- 상담사에게 QA 업무를 맡겨도 "QA 없음 · 통화 점검이 멈춰 있어요" 경고가 그대로 남는다. 승인된 문구라, 바꿀지는 사용자에게 묻는다.
- 자동 플레이가 꼼꼼함을 이름(한글)으로 찾는다. 특성 이름을 바꾸면 고르지 못한다.
- QA 지원자 알림은 특성 이름을 세이브에 저장한다. 특성 이름을 바꿔도 이미 온 알림은 옛 이름을 보여 준다.
